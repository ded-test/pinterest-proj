Создавай отдельные схемы для:
- Создания (Create) - данные для создания объекта
- Обновления (Update) - данные для частичного обновления
- Ответа (Response) - данные, возвращаемые клиенту
- БД (InDB) - полная внутреннее представление (то есть то что мы берем из бд)

Примерная иерархия по наследованию:

               Base 
                 |
            Create/Update (входные данные)
                 | 
            InDB (полная модель из БД)
                 |
            Response (то, что видит клиент)               

Для каждой модели БД создавайте 4 типа схем:

    a) BaseSchema (вместо Schema пишут названия, пример BaseUser, BasePhoto)
    Базовые поля без ID и timestamp
    Для повторного использования

    b) CreateSchema
    Поля, необходимые для создания
    Валидация входных данных
    Без ID и автоматических полей

    c) UpdateSchema
    Все поля optional
    Для PATCH запросов

    d) ResponseSchema
    Только то, что нужно клиенту
    Без чувствительных данных
    Включает связанные объекты


Так же тут можно валидировать данные

Типы валидации:

    Синтаксическая (формат данных)

        Email, URL, regex patterns
        Минимальная/максимальная длина

    Семантическая (бизнес-логика)

        Уникальность email/username
        Существование foreign keys
        Права доступа
